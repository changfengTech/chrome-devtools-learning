# T02 · Android 真机远程调试

由 pnpm docs:lessons 生成；内容源 src/data/advanced.json，合同源 scripts/generate-advanced.mjs。含教师参考答案。前置：25、48。

## 目标与原理

连接设备、选择目标并访问本地服务。手机的 localhost 指手机；远程 DevTools 目标和 HTTP 端口转发是两条连接。

### 设备连接

开发者选项、USB debugging、数据线、解锁与信任决定设备发现。

### 服务连接

在 chrome://inspect/#devices 配置端口转发，手机端 localhost:4174 指向电脑服务。

### 真机差异

记录设备 Chrome、触摸、输入法、帧率；测性能时关闭 screencast。

## 交互演示

演示手机、电脑与服务连接。改变本课输入条件并预测结果；对照请求、状态或约束的关系；切换最小修复并复位，核对改变的范围。综合题先提交判断再解锁因果模型，所有模型不计完成。

## 商城实战

电脑能访问商城，手机打开同一地址却失败，或端口转发到了错误服务。

1. 运行本地准备检查，确认商城健康端点与两个连接的区别。
2. 有 Android 时开启开发者选项和 USB debugging，连接数据线并在设备确认信任。
3. 电脑 chrome://inspect/#devices 勾选 Discover USB devices，记录设备与 Chrome 版本。
4. Port forwarding 配置 4174→localhost:4174；在手机打开本次会话地址并选择 Inspect。
5. 真机操作筛选、键盘输入、加购，记录与 Device Mode 的差异；测量时关闭 screencast。
6. 没有设备时只完成准备流程并标记待真机；结束撤销转发与调试授权。

## 独立挑战与参考答案

比较模拟与真机差异并提交证据。新输入与两种故障随机；可能再次抽到同种，不保证轮流。

| 配置 | 根因 | 实际证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | 把手机 loopback 当成电脑，未配置对应转发 | 本地健康端点正常，但拓扑中手机端口没有映射 | 配置手机 4174→电脑 localhost:4174，再 Inspect 目标页 |
| 配置2 | 目标端口映射到不存在的 HTTP 服务 | 转发目标不是电脑 4174，健康检查返回连接失败 | 纠正转发目标到实际 4174，并检查相同会话地址 |
| 干扰项 | 只根据表面现象修改无关条件 | 没有保留条件与输入的一次截图 | 同时改变设备、数据与逻辑，只保留成功结果 |

## 三级提示

1. 先复现 电脑能访问商城，手机打开同一地址却失败，或端口转发到了错误服务。
2. 对照实际证据：本地健康端点正常，但拓扑中手机端口没有映射；或 转发目标不是电脑 4174，健康检查返回连接失败
3. 一次只改变对应原因：配置手机 4174→电脑 localhost:4174，再 Inspect 目标页；或 纠正转发目标到实际 4174，并检查相同会话地址

## 验收、边界与恢复

本地拓扑练习不冒称 Android 已连接；设备步骤独立自报，可标记待验证。 保持输入、数量、环境一致；完成故障与正常对照，选择一致证据；三轮引导和两配置挑战分别取证，原生步骤与本地结果分列。停止后清理本会话资源，再恢复浏览器设置。
