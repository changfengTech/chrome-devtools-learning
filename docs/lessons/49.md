# 49 · Issues 与 Privacy and security

由 pnpm docs:lessons 生成。内容源 src/data/quality.json；生成与合同 scripts/generate-quality.mjs。本页含教师参考答案。

## 学习目标与原理

从提示追到证书、资源与隐私限制。从 Issues 或 Console 提示追到具体资源、响应头、来源和阻断原因。连接安全、内容策略和 Cookie 接收是不同问题；不要为消除提示关闭保护。

### 关联受阻对象

查看 CSP 的 effectiveDirective / blockedURI 与源脚本，或 Set-Cookie 和被拒原因，不能仅根据 Issues 条数猜根因。

### localhost 的边界

本地 HTTP 可以属于 potentially trustworthy / secure context，但并没有 TLS 证书。isSecureContext 为 true 不等于经过 HTTPS 加密。

### 最小修复

把需要执行的逻辑移到允许的同源外部脚本；Cookie 去掉错误 Domain 使用本机 host-only。不要全局放宽策略或关闭隐私保护。

## 交互演示

对应提示、请求、源和连接信息。选择 CSP / Cookie / 连接提示；沿规则、源与请求找到受影响功能；选择最小修改，对照恢复而非清空提示。模型不计完成。

## 商城实战

优惠脚本被 CSP 拦截，或服务设置的会话 Cookie 因 Domain 不属于当前站点而被浏览器拒绝。

1. 准备故障，打开 Issues、Console 和 Privacy and security，记录当前源与协议。
2. 执行优惠 / 会话检查，定位被拒的 inline script 或 Set-Cookie Domain；关联真实响应与请求。
3. 在安全面板区分连接与内容限制：本机 HTTP 没有 TLS 证书；不要绕过浏览器证书警告。
4. 选择同源外部脚本或 host-only Cookie 对照，重新执行；只清理本会话 Cookie。
5. 核对优惠实际可用或后续 profile 请求带会话；其它提示不代表本功能仍失败。
6. 恢复实验并写下原因、请求 / 规则证据和未覆盖的 HTTPS / 跨站场景。

## 独立挑战与答案

区分相关提示和根因并验证。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | CSP 拒绝没有授权的内联优惠脚本 | securitypolicyviolation 指向 script-src 和 inline | 改用被策略允许的同源外部脚本 |
| 配置2 | Cookie Domain 与当前站点不匹配而被拒 | Set-Cookie 含无关 Domain，后续 profile 不含会话 | 使用当前站点的 host-only Cookie |
| 干扰项 | isSecureContext 为 true 就说明具有 TLS 证书 | 只有 Issues 总数，没有具体资源或规则 | 关闭 CSP 或浏览器隐私保护 |

## 三级提示

1. 准备故障，打开 Issues、Console 和 Privacy and security，记录当前源与协议。
2. 在安全面板区分连接与内容限制：本机 HTTP 没有 TLS 证书；不要绕过浏览器证书警告。
3. 比较两种可能原因：CSP 拒绝没有授权的内联优惠脚本；Cookie Domain 与当前站点不匹配而被拒。用本次实际证据选择最小对照。

## 边界、恢复与来源

固定版本、设备、限速、状态和类别；保留正常 SKU / 数量。真实报告、页面结果与工具操作分列，结束后恢复覆盖、视口和限速；不把课堂结论当作全面质量认证。
