# 03 · 管理实验条件

由 `pnpm docs:lessons` 生成。脚本数据：`src/data/foundations.json`；实验合同补充：`scripts/generate-foundations.mjs`。本页含教师参考答案，独立挑战前可先不阅读。

## 学习目标与先修

理解源与端口，记录缓存、限速和窗口条件。前置：已完成前 2 课或掌握等效基础。

## 原理与交互演示

同源由协议、主机和端口共同决定；复测要保持缓存、网络、输入和视口一致。

页面演示：改变协议、主机、端口，对比实验条件。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 切换端口检查同源。
2. 记录数量与实验延迟。
3. 只改变一个条件。
4. 恢复 DevTools 限速。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### origin 由三部分组成

源由协议、主机和有效端口共同决定，路径不参与同源判断。http://127.0.0.1:5173 和 http://127.0.0.1:4174 是不同源，存储和执行环境要分别看。

### 比较结果先比较条件

数量、缓存、限速和服务状态都可能改变结果。仅仅比较“这次快了”或“金额变了”不能证明修复有效；要记录输入并保持其他条件一致。

### 响应证据有适用范围

本课 data 的 X-Lab-Condition 是教学服务提供的辅助说明，quantity 与 baselineQuantity 是真实输入。请求慢在哪里仍要看 Timing，不能把这个教学响应头当成线上通用诊断规则。

## 商城实战与实验合同

症状：实验页的网络条件或输入条件变化，导致两次运行不可直接比较。

正常结果：相同数量、正常请求条件下再比较结果。

实现与可观察对象：配置一在响应头前实际等待；配置二实际更改 quantity，保留 baselineQuantity 供对照。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Network 勾选 Preserve log，筛选 foundations/data；记录当前限速是否为 No throttling。
3. 展开故障请求的 Headers / Response / Timing；读取 X-Lab-Condition、quantity 和 baselineQuantity。
4. Console 运行 location.origin，分别记录教程 5173/4173 与商城 4174；只改变相关条件后再比较。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 独立挑战与答案

解释两次结果差异并设计公平复测。挑战变更输入与故障配置，不能仅凭引导案例的位置或数值选择。先复现并修复，再回教程选择原因、证据和验证。

| 配置 | 原因 | 可核对证据 | 参考修复/验证 |
| --- | --- | --- | --- |
| 配置1 | 额外网络等待改变了条件 | X-Lab-Condition 与响应前等待不同 | 恢复网络条件后用相同输入复测 |
| 配置2 | 商品数量改变了条件 | quantity 与 baselineQuantity 的输入不同 | 恢复数量后保持其他条件复测 |
| 干扰项 | 只是按钮文字改变 | 只看是否 200 | 同时改变所有设置 |

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Network 检查 data 响应中的 quantity / baselineQuantity 与 X-Lab-Condition；对比本页与 iframe 的 origin。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

本课等待来自服务端注入约 450ms；不是浏览器限速造成的真实线上诊断。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
