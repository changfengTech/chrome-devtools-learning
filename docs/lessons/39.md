## 目标与原理

检查 Cache Storage、策略与 Manifest。先修按 [完整目录](../CURRICULUM.md) 的章节关系；基础操作、原理关系随本课讲解。

Cache Storage 是脚本管理的缓存，不等于 HTTP 缓存；Manifest 是应用元数据。

### 先建立边界

cache-first 可优先返回旧内容；network-first 需要失败回退

### 再核对证据

删除 HTTP 缓存或勾 Disable cache 不自动删除 Cache Storage

### 最后验证结果

Manifest 的 scope、start_url、图标路径要可访问；本课不宣称完整 PWA 安装认证

## 交互演示

## 真实商城合同

症状：离线商品仍旧，或 Manifest 引用的图标不存在。

正常结果：商品与缓存更新到版本 2，Manifest 图标实际 200，网络失败可回退到缓存副本。

真实机制：真实 Cache Storage、network-first/cache-first worker、Manifest 与图标请求。

1. 从本课准备并打开独立商城；先打开 DevTools，再运行故障。
2. Application 检查 Cache Storage 的会话缓存，再到 Network 比较资源版本与来源。
3. 查看 Manifest 的 scope、start_url、icons，并打开图标请求验证是否真实可用。
4. 对照后选择 Offline 并点「离线读取」，验证实际 worker 缓存回退；恢复 Online 再报告，并仅清理本实验。
5. 先保存证据，再应用针对性的对照；错误对照不会通过页面检查。
6. 回到教程选择真实证据，完成独立挑战后写下排查与恢复步骤。

## 独立挑战与参考答案

找到旧页面的缓存层并验证修复。新会话改变输入与故障配置，可能再次抽到同一类型；按实际证据判断。

| 配置 | 原因 | 证据 | 修复/验证 |
| --- | --- | --- | --- |
| 配置1 | cache-first 优先返回旧 Cache Storage 响应 | Cache Storage 的商品版本 1，网络资源已是版本 2 | 改用网络优先并更新缓存，再离线复查 |
| 配置2 | Manifest 引用不存在的图标 | Manifest 的 icon 地址返回 404，其他数据正确 | 修正图标路径并验证实际资源 |
| 干扰项 | 只凭界面颜色判断 | 没有对应请求或存储证据 | 同时改变全部条件且不复测 |

## 边界与恢复

缓存回退标为 cache-storage-fallback。仅页面 CDP Offline 不保证 worker 网络也被阻断；验收需确认真正网络失败。

清理与会话约定见 [共同合同](../NETWORK-APPLICATION.md)。请在复盘写下条件、观察对象、实际值、根因、最小修改与恢复设置；将 HTTP 缓存、Cache Storage、内存状态分开。

[官方参考](https://developer.chrome.com/docs/devtools/storage/cache)。实测范围见 [验收记录](../QA-NETWORK-APPLICATION.md)。
