操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 引用与快照保留不同信息

对象日志可能在后来展开时读取属性，具体呈现取决于浏览器与对象状态。需要证明“当时是什么”时，保存原始字段或 JSON 快照，并说明记录时机。

### 计时边界决定测量含义

console.time / timeEnd 测两次调用之间的时间。启动 Promise 后马上 timeEnd 只测到启动成本；await 完成再结束才包含异步等待。

### 一次耗时不能当成结论

定时器、机器负载和调试暂停会影响时间。先说明测的是哪一段，再在相同条件下重复比较；Snippet 适合保存可重复的取证表达式。

## 商城实战与实验合同

症状：日志对象被稍后修改，或者异步计时在请求完成前就结束。

正常结果：用于取证的快照保留记录时 price；完整计时包含 await。

实现与可观察对象：真实对象后续变化与 Promise 定时任务；可在 Snippet 保存 JSON 快照再复测。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Console 保留 [snapshot] 和 [live] 两组记录，展开对象并与原始快照字符串比较。
3. Sources → Snippets 新建临时取证片段，保存需要的原始字段；不要依靠稍后展开的对象证明历史值。
4. 查看 checkout-time 的起止代码，区分启动 Promise 和 await 完成；修复后重复测量并注明环境。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Console 比较 [snapshot] JSON 与 [live] 对象；查看 checkout-time 的起止，运行 Snippet 保存需要的原始值。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

对象展开受浏览器呈现时机影响；优先比较保存的原始字段。约 40ms 定时器不是性能基准。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
