## 学习目标与先修

## 原理与交互演示

交互需要同时检查实际点击目标、disabled 状态、伪类和监听器。hover 外观不能证明按钮能接收点击。

页面演示：切换 hover、focus、disabled 与覆盖层。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 切换覆盖层。
2. 切换 disabled。
3. 强制 focus / hover。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 看得见不等于点得到

浏览器根据层叠与命中测试决定点击目标。透明元素仍可能接收指针事件；覆盖层看起来空白，也能挡住下面的按钮。

### 状态、属性和监听器不同

disabled 会让原生按钮不可用；:hover / :focus 是状态样式；监听器执行实际业务。强制 :hover 只便于查看样式，不会补上监听器，也不会解除禁用。

### 按事件链验证

先确认鼠标命中的元素，再看 disabled、Event Listeners 和实际数量变化。去除覆盖或禁用后用相同输入再点一次，同时检查键盘能否操作。

## 商城实战与实验合同

症状：按钮上方存在覆盖层，或者按钮被禁用。

正常结果：可用按钮能收到点击，并使购物车数量增加。

实现与可观察对象：覆盖层与禁用属性是真实 DOM；可在 Elements 去除拦截/属性后再触发一次业务并检查。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Inspect 按钮所在位置，确认选中的是 #add 还是 #click-shield；查看覆盖层和 disabled 属性。
3. Styles 的 :hov 可强制 hover/focus 查看样式；再检查 Event Listeners，区分状态与处理函数。
4. 取消指针拦截或 disabled 后点「再次触发业务」；核对数量变化，再点「检查当前页面」。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Elements → :hov 检查 hover/focus；观察按钮 disabled 与 #click-shield，点击一次验证计数。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

:hover / :focus 强制状态用于查看样式，不能修复透明覆盖层或 disabled。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。
