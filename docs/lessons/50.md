# 50 · Recorder 复现与回归

由 pnpm docs:lessons 生成。内容源 src/data/memory.json；生成与合同 scripts/generate-memory.mjs。本页含教师参考答案。

## 学习目标与原理

录制、编辑、重放稳定的用户流程。稳定回归需要明确起点、语义或业务定位、条件等待与结果断言。Recorder 负责录制和回放，示例流程只帮助解释失败，不替代工具操作。

### 定位业务对象

nth-child 与易变顺序绑定。使用稳定的 data-testid 或可访问名称，并检查目标 SKU；不要复制会话 token 到长期测试环境。

### 等待状态

Recorder 自动等待可交互元素，也可以添加 waitForElement / asserted events。固定 sleep 无法表达结果已准备好；录制真实异步状态。

### 可复现的起点

每轮先重置搜索与购物车，再执行搜索→目标详情→加购；重复两种排序与两种延迟，断言 SKU、数量、总额。会话 30 分钟过期后需重新生成链接。

## 交互演示

改变定位和等待条件观察回放。切换商品排序和搜索延迟；比较第一项 / 固定等待与 SKU / 条件等待；查看定位失败、等待失败和业务断言的不同结果。模型不计完成。

## 商城实战

按第一个商品录制的流程在排序变化后买错商品；固定等待的流程在搜索变慢后找不到结果。

1. 准备实验，打开 More tools > Recorder；记录前先点重置购物流程，保证购物车为空。
2. 先运行脆弱示例观察失败；示例是页面教学脚本，不是 Recorder 回放。
3. Start new recording，设置 Selector attribute 为 data-testid；录制重置→输入杯→搜索→查看晨间陶瓷杯→加入购物车。
4. 结束录制，检查步骤；用 Recorder 编辑稳定定位、添加结果条件或 waitForElement，断言目标 SKU 与购物车完成状态。
5. 首次 Replay 核对起点。测试新顺序 / 延迟时，移除 Recorder 默认 navigate 步骤（保留重置），或编辑导航 URL 条件；至少两种条件都断言相同 SKU、数量与总额。会话专用 JSON 示例可下载作编辑参考。
6. 保存 / 导出 Recorder 用户流程与回放证据，回教程选择证据。页面只检查实际购物结果，不能证明你操作过 Recorder。

## 独立挑战与答案

制作不依赖易变商品顺序的流程。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | 按第一项定位把商品顺序当作身份 | 换序后第一项变为另一 SKU，购物车断言失败 | 使用目标商品业务定位并核对购物车 SKU |
| 配置2 | 固定等待比真实搜索完成更短 | 结果未就绪时固定等待已结束；条件等待仍能完成 | 等待结果就绪与业务条件后继续 |
| 干扰项 | 只要按钮点击成功就算回归通过 | 只有一次成功截图，没有多条件回放 | 把等待写得很长且不检查结果 |

## 三级提示

1. 准备实验，打开 More tools > Recorder；记录前先点重置购物流程，保证购物车为空。
2. Start new recording，设置 Selector attribute 为 data-testid；录制重置→输入杯→搜索→查看晨间陶瓷杯→加入购物车。
3. 核对两条可能的保留或回归原因：按第一项定位把商品顺序当作身份；固定等待比真实搜索完成更短。保持正常结果并复测。

## 边界、恢复与来源

正常结果保持 SKU、数量与业务校验值一致。相同 VM、批次和空闲条件比较；停止只清理本页资源。实际 GC、快照与 Recorder 证据须在工具核对，页面容器计数不等于堆快照。
