## 原理与交互演示

Styles 展示规则来源，Computed 展示最终值。先看胜出的规则，再解释层叠、优先级和顺序。

页面演示：切换选择器和声明顺序，预测最终样式。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 切换选择器权重。
2. 交换规则顺序。
3. 预测最终颜色。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 先确认规则是否匹配

选中目标后，Styles 展示匹配规则，划掉的声明通常没有获胜。先检查选择器、拼写和来源，再追是谁覆盖；不要先叠加 !important。

### 权重比较有前提

在相同来源、层和重要性等前提下，ID 比 class 更具体；权重相同时通常后面的声明获胜。教学模型简化了 cascade，真实页面还可能有继承、层与重要性因素。

### 用最终值验证

Styles 帮你找声明来源，Computed 帮你确认最终使用的值。修正规则后看 computed color，并检查相邻商品，避免一个过强选择器带来新的影响。

## 商城实战与实验合同

症状：促销价格应该为绿色，实际被更高优先级或同级后置规则覆盖。

正常结果：#price-value 的最终计算颜色为 rgb(22, 130, 103)。

实现与可观察对象：配置一 ID 权重覆盖 class；配置二同权重后置覆盖。用 Styles 找来源、Computed 验证。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Inspect 价格，Styles 筛选 color，找到划掉的 .sale-price 和真正获胜的规则。
3. 点击规则来源定位 #fault-style；先判断是 ID 权重还是同级后置覆盖。
4. 修改获胜声明，再到 Computed 筛选 color，确认 rgb(22, 130, 103)，检查相邻内容没有被误改。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

| 配置 | 原因 | 可核对证据 | 参考修复/验证 |

| 配置1 | ID 选择器覆盖了 class 规则 | 被划掉的 class 与胜出的 ID 规则 | 修正过强规则的声明 |

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. 选择 #price-value，Styles 筛选 color，追到 #fault-style；用 Computed 验证最终 rgb(22, 130, 103)。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。
