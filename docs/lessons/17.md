# 17 · 从行为追到代码

由 `pnpm docs:lessons` 生成。脚本数据：`src/data/foundations.json`；实验合同补充：`scripts/generate-foundations.mjs`。本页含教师参考答案，独立挑战前可先不阅读。

## 学习目标与先修

使用事件、DOM、XHR/fetch 断点。前置：已完成前 16 课或掌握等效基础。

## 原理与交互演示

用事件、DOM 和 XHR/fetch 断点从行为进入代码，定位是谁改变了状态或发起请求。

页面演示：将行为映射到不同暂停入口。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 将行为与断点类型配对。
2. 切换触发动作。
3. 观察暂停来源。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 不知道入口时从行为反查

知道哪个节点被改，却不知道哪个函数负责时，可以在 Elements 对目标设置 DOM 断点。下一次实际修改会在相关代码位置暂停。

### 事件和请求有不同断点入口

Event Listener Breakpoints 从 click 等事件开始；XHR/fetch Breakpoints 按 URL 子串匹配请求调用。Network 看发送结果，Sources 在发起前检查调用原因。

### 重复结果要追不同调用

同一次业务可能有两个监听器改 DOM，也可能只改一次却发两次请求。比较调用栈与实际 trace 请求次数，找到重复发生在哪一层再消除它。

## 商城实战与实验合同

症状：一次加购导致计数重复修改，或者一个动作发出了重复请求。

正常结果：单次动作只有一次状态变化与一次 trace 请求。

实现与可观察对象：配置一两个监听器修改 #cart-count；配置二真实发两次 /api/foundations/trace HTTP 请求。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Elements 选 #cart-count，右键 Break on → Subtree modifications；点「再次触发业务」，追两次修改的调用者。
3. Sources 的 XHR/fetch Breakpoints 添加 /api/foundations/trace，再触发并检查发起调用。
4. 结合 Event Listener Breakpoints 的 Mouse → click 与 Network 的 trace 次数，区分重复监听和重复请求；结束清理断点。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 独立挑战与答案

为未知触发函数选择断点。挑战变更输入与故障配置，不能仅凭引导案例的位置或数值选择。先复现并修复，再回教程选择原因、证据和验证。

| 配置 | 原因 | 可核对证据 | 参考修复/验证 |
| --- | --- | --- | --- |
| 配置1 | 同一动作的两个监听器都修改 DOM | 两个调用分别修改同一节点 | 去掉重复的状态修改监听器 |
| 配置2 | 同一动作重复发起 trace 请求 | 相同动作产生两次 trace 调用 | 保留一次请求调用 |
| 干扰项 | 图片懒加载失败 | 看加载动画持续时间 | 隐藏 Network 面板 |

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. 对 #cart-count 设置 Break on → Subtree modifications；为 /api/foundations/trace 设置 XHR/fetch 断点，再检查 click 事件。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

DOM 断点会在修改处暂停；XHR/fetch 断点按 URL 子串匹配，在发起调用前暂停。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
