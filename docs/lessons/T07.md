## 目标与原理

组织上下文并用工具检查建议。给出上下文、实际证据和预期，让工具检查建议；生成式回答不是事实，功能不可用也能完成验证练习。

### 选择上下文

定位实际元素、请求或 trace，描述稳定复现和已排除项。

### 最小验证

本课提供预置建议供批判，不发送真实 AI 请求；逐条保留或推翻。

### 可用性与数据

AI assistance 受版本、地区、账号及管理策略影响；只用本地合成内容。

## 交互演示

比较有无证据的建议。改变本课输入条件并预测结果；对照请求、状态或约束的关系；切换最小修复并复位，核对改变的范围。综合题先提交判断再解锁因果模型，所有模型不计完成。

## 商城实战

建议修改 z-index 或颜色，但没有解释为什么按钮仍点不到。

1. 记录当前元素、实际命中目标和业务预期，阅读明确标注的预置待验证建议。
2. 写一条包含证据、条件和问题的上下文，避免只问“为什么不工作”。
3. 功能可用时从实际 Elements / Network / Performance / Sources 上下文打开 AI assistance。
4. 检查建议引用的事实，用实际样式、命中测试或调用栈验证；不可用时完成同一批判流程。
5. 应用最小对应对照，保留被推翻的假设与反例。
6. 结束恢复修改；不要提交私人页面、账号或敏感请求内容。

## 独立挑战与参考答案

找出未验证假设并提交验证。新输入与两种故障随机；可能再次抽到同种，不保证轮流。

| 配置 | 根因 | 实际证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | 按钮被透明层拦截，修改颜色无法恢复点击 | elementFromPoint 命中覆盖层，按钮并未收到点击 | 移除拦截层的 pointer-events，验证业务与邻近交互 |
| 配置2 | 按钮自身 disabled，提升 z-index 无效 | 元素 disabled=true，没有发生预期业务处理 | 修复禁用条件并核对库存，不盲目覆盖 CSS |
| 干扰项 | 只根据表面现象修改无关条件 | 没有保留条件与输入的一次截图 | 同时改变设备、数据与逻辑，只保留成功结果 |

## 三级提示

1. 先复现 建议修改 z-index 或颜色，但没有解释为什么按钮仍点不到。
2. 对照实际证据：elementFromPoint 命中覆盖层，按钮并未收到点击；或 元素 disabled=true，没有发生预期业务处理
3. 一次只改变对应原因：移除拦截层的 pointer-events，验证业务与邻近交互；或 修复禁用条件并核对库存，不盲目覆盖 CSS

## 验收、边界与恢复

站内建议为预置练习材料，不伪造 AI 响应；不自动启用云端功能或发送内容。 保持输入、数量、环境一致；完成故障与正常对照，选择一致证据；三轮引导和两配置挑战分别取证，原生步骤与本地结果分列。停止后清理本会话资源，再恢复浏览器设置。
