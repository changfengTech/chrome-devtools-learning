# 45 · 正确运行一次审计

由 pnpm docs:lessons 生成。内容源 src/data/quality.json；生成与合同 scripts/generate-quality.mjs。本页含教师参考答案。

## 学习目标与原理

理解模式、设备、类别和实验室结果边界。审计模式、页面状态、设备与类别决定报告能回答什么。Navigation、Timespan、Snapshot 的范围不同；实验室分数不等于线上用户体验。

### 先选观察范围

Navigation 从新导航测加载；Timespan 观察一段操作；Snapshot 检查当前状态且不重新加载。具体支持项随版本和模式变化。

### 记录条件再比较

保存 form factor、类别、限速方式、版本、URL、状态与清理选项；跨条件分数不能直接比高低。

### 真实报告与自报边界

本页只解析你导入的 Lighthouse JSON，显示其中的分数；不会生成模拟分数。导入不能证明你操作过原生面板。

## 交互演示

改变运行条件比较报告。选择加载 / 交互区间 / 当前弹窗的目标；改变模式、设备和类别，观察可回答的问题；对照两个条件记录，不演算虚构分数。模型不计完成。

## 商城实战

同一商城得到了不同分数：一份使用桌面条件，另一份只勾选了 Performance，不能回答原来的问题。

1. 从课程打开实验，准备故障；打开本轮独立审计目标。记录 URL、目标状态与设备条件。
2. 在 DevTools Lighthouse 识别 Navigation / Timespan / Snapshot；为首次加载选择 Navigation，当前展开状态使用 Snapshot，交互区间使用 Timespan。
3. 本课引导故意用 Desktop 运行；另一配置只跑 Performance。导出真实 JSON 并导入本页，先识别条件不匹配。
4. 针对本次目标选择正确 Mobile 条件，或完整四类结果；不要通过改变所有条件追求分数。
5. 应用对应服务器对照，审计新的目标地址，导入同一轮报告，核对类别、formFactor、版本和时间。
6. 回教程说明报告回答了什么、不能回答什么。CLI Navigation 与原生 Timespan / Snapshot 的实测分开记录。

## 独立挑战与答案

为加载与特定状态选择审计方式。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | 用 Desktop 报告回答 Mobile 首次加载问题 | 报告 configSettings.formFactor 与 Mobile 目标不符 | 固定 Mobile 与所需类别，重新导航审计 |
| 配置2 | 只选择 Performance 却声称覆盖四类质量 | categories 中缺 accessibility / best-practices / seo | 保持 Desktop 目标并补齐四类审计 |
| 干扰项 | 把一次总分当作线上所有用户体验 | 不同版本和条件的分数差异就是修复效果 | 改设备、限速、URL 后只保留最高分 |

## 三级提示

1. 从课程打开实验，准备故障；打开本轮独立审计目标。记录 URL、目标状态与设备条件。
2. 本课引导故意用 Desktop 运行；另一配置只跑 Performance。导出真实 JSON 并导入本页，先识别条件不匹配。
3. 比较两种可能原因：用 Desktop 报告回答 Mobile 首次加载问题；只选择 Performance 却声称覆盖四类质量。用本次实际证据选择最小对照。

## 边界、恢复与来源

固定版本、设备、限速、状态和类别；保留正常 SKU / 数量。真实报告、页面结果与工具操作分列，结束后恢复覆盖、视口和限速；不把课堂结论当作全面质量认证。
