## 学习目标与原理

理解监听器、定时器、闭包和缓存保留。监听器和定时器会保留回调及其闭包。业务结束时必须撤销注册并放下清理记录；只隐藏节点或重新赋值变量都不够。

### 监听器的身份

removeEventListener 需要对应事件类型、原函数与 capture 条件。每次创建新箭头函数不能移除旧回调。

### 定时器与闭包

clearInterval 使用原 ID；回调仍注册时，它捕获的 TimerLease 也可能可达。清理后再丢弃 cleanup 闭包本身。

### 清理与可用性

为自己的每次订阅登记 dispose，并在关闭 / reset / pagehide 撤销。修复后再次打开仍应收到一次库存更新，不能用禁用功能蒙混。

## 商城实战

商品详情反复关闭后，库存事件仍触发多份回调，或定时刷新继续持有已经结束的会话。

1. 记录基线 JS event listeners 与快照，准备故障并反复 5 次开关。
2. 触发库存事件，观察回调数；定时配置等两个 tick，再拍快照。
3. 筛选 SubscriptionLease / TimerLease，沿回调闭包追到事件目标或调度器。
4. 应用对应取消注册 / clearInterval 对照，同时清空已结束的清理登记。
5. 重复相同开关，验证闲置资源为零；重新打开，库存或刷新仍能更新一次。
6. 离开前停止并清理本页资源，比较多批存活趋势；计数只覆盖实验自己注册的资源。

## 独立挑战与答案

修复新保留问题并保证功能正常。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | window 库存事件回调未在关闭时注销 | SubscriptionLease 经库存监听器闭包可达，关闭后事件仍触发 | 用原回调注销库存事件并释放登记 |
| 配置2 | setInterval 未在关闭时 clearInterval | TimerLease 经 interval 闭包可达，关闭后仍有 tick | clearInterval 原 ID 并释放闭包登记 |
| 干扰项 | 只是浏览器 GC 不够积极 | 只看 DOM 是否从页面消失 | 只删除弹窗节点 |

## 三级提示

1. 记录基线 JS event listeners 与快照，准备故障并反复 5 次开关。
2. 筛选 SubscriptionLease / TimerLease，沿回调闭包追到事件目标或调度器。
3. 核对两条可能的保留或回归原因：window 库存事件回调未在关闭时注销；setInterval 未在关闭时 clearInterval。保持正常结果并复测。

## 边界、恢复与来源

正常结果保持 SKU、数量与业务校验值一致。相同 VM、批次和空闲条件比较；停止只清理本页资源。实际 GC、快照与 Recorder 证据须在工具核对，页面容器计数不等于堆快照。
