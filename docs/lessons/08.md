## 原理与交互演示

1. 修改 aria-label。

### 语义提供另一种页面视图

可访问性树由 DOM、语义和样式等信息生成。辅助技术关心 role、name 和 state；一个心形图案能被看见，并不说明按钮有准确的可访问性名称。

### label 关联具体控件

label 的 for 必须匹配 input 的 id；正确关联能提供名称，并让点击标签聚焦输入。placeholder 和旁边一段文字不能自动代替这种关系。

### 键盘检查要实际操作

Tab 逐项移动焦点，观察可见焦点；按钮用 Space 或 Enter 操作。本课自动检查名称和关联，焦点顺序、实际读屏体验仍需人工核对。

## 商城实战与实验合同

症状：图标按钮没有名称，或者输入框缺少正确关联的标签。

正常结果：收藏按钮存在准确 name；label.control 指向数量输入。

实现与可观察对象：用 Accessibility 与 Tab/Space 验证，区分缺失 aria-label 与错误 label[for]。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Elements 选择 #icon-favorite，打开 Accessibility，查看 role、name；确认 ♡ 是图案还是可访问性名称。
3. 检查 #quantity-label 的 for 与输入 id；修改名称或关联后重新查看 Accessibility。
4. 用 Tab 移动焦点、Space/Enter 操作；观察可见焦点及按钮状态，再提交页面检查。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Elements → Accessibility 检查 #icon-favorite 与 #quantity；用 Tab 和 Space 操作按钮，并观察 :focus-visible。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

自动检查只覆盖名称与关联；键盘操作、焦点顺序及语义仍需人工检查。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。
