# 01 · 认识 DevTools

由 `pnpm docs:lessons` 生成。脚本数据：`src/data/foundations.json`；实验合同补充：`scripts/generate-foundations.mjs`。本页含教师参考答案，独立挑战前可先不阅读。

## 学习目标与先修

知道八大面板的职责，会使用停靠、Drawer 与 Command Menu。前置：懂一点 HTML、CSS 和 JavaScript，普通语法随例子解释。

## 原理与交互演示

把症状与工具的观察对象连起来。面板选择是起点，后面还要用证据验证。

页面演示：将故障与工具配对，查看跨面板关系。这是可重置的教学模型，演示本身不写入实战完成记录。

1. Elements：看 DOM 和最终样式。
2. Console：检查错误和表达式。
3. Sources：暂停并检查运行状态。
4. Network：查看真实请求。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 面板观察不同层面

HTML 是文档结构，CSS 决定外观，JavaScript 改变状态，HTTP 交换数据。Elements 看当前 DOM 和样式；Console 检查值与错误；Sources 看执行过程；Network 看请求，不需要每次打开所有面板。

### 把抱怨改成可检验的预期

“加购坏了”不够具体。可以先说：数量为 2，点击一次，购物车应该增加 2。先检查当前文本，再查是谁改了它，才能逐步缩小范围。

### 工具显示的是证据

一条成功请求只能说明这次 HTTP 有响应，不能证明后续计算和渲染正确。将输入、处理和页面结果串起来，再决定下一步要看哪个面板。

## 商城实战与实验合同

症状：商品请求已完成，但购物车数量与实际操作不符。

正常结果：一次加购后，计数等于数量；数值总额等于单价 × 数量 − 优惠。

实现与可观察对象：计数错误或价格拼接；检查真实 DOM 文本与 calculateTotal。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. 右键商品价格选择 Inspect；在 Elements 找到 #price-value 与 #cart-count，核对它们代表什么。
3. Console 筛选 [cart]，再点「再次触发业务」，比较一次动作与数量变化。
4. Network 筛选 data，查看 Response；Sources 搜索 calculateTotal，判断下一步需要哪层证据。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 独立挑战与答案

为三个陌生症状选择第一步并说明理由。挑战变更输入与故障配置，不能仅凭引导案例的位置或数值选择。先复现并修复，再回教程选择原因、证据和验证。

| 配置 | 原因 | 可核对证据 | 参考修复/验证 |
| --- | --- | --- | --- |
| 配置1 | 页面计数与实际操作不一致 | DOM 文本与点击日志相互印证 | 更新正确的计数目标 |
| 配置2 | 商品价格类型与预期不一致 | 变量类型与页面合计相互印证 | 转换价格后重新计算 |
| 干扰项 | 页面截图颜色相近 | 只看工具图标 | 只重载图片 |

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. 点击一次「加入购物车」，分别定位 #cart-count、Console 日志、/api/foundations/data 请求和 shop-cart.ts。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

不按面板顺序盲逛；先说清希望验证的事实。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
