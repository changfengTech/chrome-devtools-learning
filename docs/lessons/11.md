## 原理与交互演示

Console 的执行上下文决定 document 指向哪一页。$0 是最近选中元素，查询函数的结果也受上下文影响。

页面演示：切换页面、iframe 与选中元素。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 切换父页面和 iframe。
2. 比较同一选择器。
3. 检查选中节点。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 表达式在选定上下文中运行

Console 的 top 和 iframe 对应不同全局环境。每个 document 只查询自己的节点；同一选择器在 top 为 null，在 iframe 中可能有结果。

### null 是结果，不是完整结论

querySelector 找不到匹配会返回 null，可能是拼写、上下文、时机或节点已变化。先核对当前 document 的 URL，再验证选择器，逐项排除。

### $0 与普通查询相互补充

$0 指向 Elements 最近选中的元素，适合检查属性和关联。document.querySelector 可以重复验证目标；切换上下文后再确认对象属于哪个 document。

## 商城实战与实验合同

症状：外层页面与 iframe 有不同的商品节点；另一个案例使用了错误的选择器。

正常结果：在目标 iframe document 中能查到价格节点。

实现与可观察对象：同源 iframe 是真实独立 document；切换 Console JavaScript context 后验证同一选择器。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. 运行故障后，在 Console 的 JavaScript context 下拉框选择 top，运行 document.querySelector("#frame-price")。
3. 切到商品预览 iframe，先运行 document.URL，再执行同一选择器；确认目标 document。
4. 比较 #frame-price 与拼错的 #frame-prcie；在 Elements 选中价格后检查 $0，并核对其 ownerDocument.URL。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Console 切换 top / 商品预览 iframe，运行 document.querySelector("#frame-price")；检查 $0 与 data-sku。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

查询结果为 null 也可能是选择器错误、运行时机或上下文问题；不能直接断言节点不存在。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。
