# 46 · 读懂四类结果

由 pnpm docs:lessons 生成。内容源 src/data/quality.json；生成与合同 scripts/generate-quality.mjs。本页含教师参考答案。

## 学习目标与原理

从检查项追证据，理解自动检查边界。Performance、Accessibility、Best Practices、SEO 从不同角度检查质量。先读具体 audit 和元素 / 请求证据，再做人工补充；自动通过不是全面合格。

### 检查项比总分具体

使用 audit ID、details 与元素片段关联实际页面。button-name 与 meta-description 对应不同根因。

### 自动检查有边界

名称存在不保证名称合适；自动 accessibility 检查不能替代键盘路径、读屏与业务可理解性。SEO 分数不是搜索排名。

### 修复保持业务

补语义和元信息，验证按钮仍可打开详情与加入同一商品；不要靠删控件或隐藏内容通过。

## 交互演示

关联报告与资源、语义和页面。选择报告类别与具体检查项；定位关联元素、资源或文档；打开人工检查清单，区分自动发现与人工结论。模型不计完成。

## 商城实战

图标按钮没有名称，或商品页缺少描述；报告给出检查项，但仍有人无法用键盘完成操作。

1. 准备故障并打开目标，在相同条件下运行四类 Lighthouse 审计，导出 JSON。
2. 导入后展开 button-name 或 meta-description 及原始 details；到 Elements 核对真实按钮或 head。
3. 用 Tab / Enter 验证详情与加购，记录自动报告之外仍需检查的焦点、名称和业务路径。
4. 选择当前问题对应对照，重新审计新的目标；目标 audit 应恢复，但不要要求所有类别 100。
5. 导入对照报告，核对同一 audit ID 与正常 SKU、数量，勾选已实际完成的人工检查。
6. 提交原因、直接证据与验证；说明其它检查项和未覆盖范围。

## 独立挑战与答案

找出报告之外仍需手工检查的问题。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | 图标按钮缺少可访问名称 | button-name 失败并指向无名称按钮 | 为按钮补准确名称，保留实际交互 |
| 配置2 | 文档没有有效 meta description | meta-description 失败且 head 缺少 description | 补充对应商品的真实描述，复测 SEO 检查项 |
| 干扰项 | Accessibility 通过就证明所有人都能使用 | 只有总分截图，没有元素或 audit ID | 删除按钮或把内容全部隐藏 |

## 三级提示

1. 准备故障并打开目标，在相同条件下运行四类 Lighthouse 审计，导出 JSON。
2. 用 Tab / Enter 验证详情与加购，记录自动报告之外仍需检查的焦点、名称和业务路径。
3. 比较两种可能原因：图标按钮缺少可访问名称；文档没有有效 meta description。用本次实际证据选择最小对照。

## 边界、恢复与来源

固定版本、设备、限速、状态和类别；保留正常 SKU / 数量。真实报告、页面结果与工具操作分列，结束后恢复覆盖、视口和限速；不把课堂结论当作全面质量认证。
