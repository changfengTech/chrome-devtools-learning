# 18 · 捕获异常与异步问题

由 `pnpm docs:lessons` 生成。脚本数据：`src/data/foundations.json`；实验合同补充：`scripts/generate-foundations.mjs`。本页含教师参考答案，独立挑战前可先不阅读。

## 学习目标与先修

理解异常暂停、处理位置与异步执行顺序。前置：已完成前 17 课或掌握等效基础。

## 原理与交互演示

异常暂停帮助找到被捕获的抛出点；异步顺序需要记录请求与状态更新，避免旧结果覆盖新操作。

页面演示：改变异步完成顺序观察调用链。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 切换完成顺序。
2. 暂停捕获异常。
3. 关联异步调用链。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 捕获异常仍可能留下错误

try/catch 防止异常继续冒泡，不代表业务成功。默认未捕获暂停可能看不到它；开启 Pause on caught exceptions，才能在抛出位置检查原始输入。

### 异步完成不保证发起顺序

旧任务先启动却后完成，可能覆盖新任务结果。本课用两个真实定时异步任务展示该问题；网络搜索也有类似现象，但这里没有伪装 HTTP 请求。

### 区分因果与状态校验

异步调用栈帮助追踪任务来源，不是完整历史。提交结果前检查任务序号是否仍为最新；修复后即使完成顺序不变，页面也应保留新结果。

## 商城实战与实验合同

症状：错误被 catch 后只显示空白，或者旧搜索结果覆盖新结果。

正常结果：解析成功且结果正确；异步完成顺序变化后仍保留最新任务结果。

实现与可观察对象：配置一真实 JSON.parse 抛出后被捕获；配置二真实 15/90ms 定时异步任务竞争，不伪称 HTTP 搜索请求。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Sources 打开异常暂停，启用 Pause on caught exceptions；运行故障，查看 parseDiscount 的输入和 catch 后页面状态。
3. 若遇到异步覆盖案例，在 commitSearch 设断点，点「再次触发业务」启动两项任务。
4. 比较 request、latest 和完成顺序；应用修复后旧任务仍较晚完成，但页面必须保留新结果；结束恢复异常开关。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Sources 开启 Pause on caught exceptions 找到 parseDiscount；另一个案例连续搜索两次，追踪 commitSearch 与请求完成顺序。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

异常被 catch 仍可能留下业务问题；caught 开关影响暂停。异步调用栈不等于完整历史录像。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
