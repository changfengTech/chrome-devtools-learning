## 学习目标与先修

掌握复现、猜想、取证与验证，区分现象和根因。前置：已完成前 1 课或掌握等效基础。

## 原理与交互演示

记录起始状态、输入、动作和预期。看到现象后，用对照排除其他解释。

页面演示：筛选能支持或排除猜想的线索。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 先恢复现场。
2. 输入数量 2。
3. 点击一次加购。
4. 对照事件与结果。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 先稳定复现

记录起始计数、输入数量和点击次数。恢复故障后只做一次动作；重复点击、刷新或改多个选项会改变现场，让两次结果无法公平比较。

### 事件处理与页面结果

addEventListener 给事件绑定处理函数。一个 click 可以触发多个处理函数；缺少监听器则可能没有状态变化。DOM 文本和处理日志分别反映结果与过程。

### 用对照排除解释

只移除重复监听器，再用同一输入单击。如果变化从两次恢复为一次，就有证据支持重复处理。仍需检查真实绑定来源，不能把一条重复日志直接当成唯一根因。

## 商城实战与实验合同

症状：一次加购出现了两次变化，或者根本没有发生变化。

正常结果：每次单击只执行一次对应加购处理。

实现与可观察对象：在 #add 的 Event Listeners 与 [cart] 日志中区分重复绑定和缺失绑定。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. 运行故障后先记下数量与购物车变化，不要连续点击。
3. Elements 选中 #add，展开 Event Listeners 的 click；Console 过滤 [cart]。
4. 点「恢复故障」重新开始，比较一份输入对应几次处理；缺失监听器时也记录没有日志与没有变化。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 独立挑战与答案

从含干扰信息的描述整理检查顺序。挑战变更输入与故障配置，不能仅凭引导案例的位置或数值选择。先复现并修复，再回教程选择原因、证据和验证。

| 配置 | 原因 | 可核对证据 | 参考修复/验证 |
| --- | --- | --- | --- |
| 配置1 | 同一动作被两个监听器处理 | 单次操作产生两条处理日志 | 移除重复监听器再单击 |
| 配置2 | 按钮未绑定对应监听器 | 点击后没有处理日志且未产生状态变化 | 补上缺失监听器再单击 |
| 干扰项 | 商品图片下载失败 | 按钮长得很像 | 重复点击直到成功 |

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Elements → Event Listeners 检查 add 按钮。Console 过滤 [cart]，恢复故障后只点击一次按钮。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

Console 清空只清显示；恢复现场要用商城「恢复故障」。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
