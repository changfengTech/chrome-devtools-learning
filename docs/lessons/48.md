# 48 · Device Mode 与响应式检查

由 pnpm docs:lessons 生成。内容源 src/data/quality.json；生成与合同 scripts/generate-quality.mjs。本页含教师参考答案。

## 学习目标与原理

检查视口、DPR、方向、触摸和媒体查询。Device Mode 改变的是模拟条件。CSS 像素、DPR、方向与指针能力是不同维度；模拟不能替代真机性能、软键盘和手势。

### CSS 视口与物理像素

媒体查询通常按 CSS px；DPR 改变像素密度与资源选择，不应把布局宽度简单乘以 DPR。

### 条件分别验证

记录 innerWidth、devicePixelRatio、orientation、pointer / hover 与 currentSrc；缩放浏览器窗口不自动等于移动触摸。

### 从模拟到真机

在 320 / 390、768、1440 检查网格、筛选与购物车，再列出真机软键盘、触控、滚动、安全区域及性能检查。

## 交互演示

切换设备条件观察变化。独立切换视口、DPR、方向和指针；观察媒体查询、示意布局与资源选择；比较模拟覆盖范围与真机待办。模型不计完成。

## 商城实战

窄屏商品网格撑出页面，或筛选面板仍保持桌面固定宽度，关键操作跑到视口外。

1. 准备故障，在 Device Mode 设 390 CSS px 并记录实际 innerWidth；本课检查需在 280–500 的窄视口进行。
2. 打开筛选和加入购物车，检查根文档 scrollWidth、网格与面板边界；不要用截屏缩放代替检查。
3. 改变 DPR 与方向，读当前图片 currentSrc、pointer / hover 条件；浏览器可自行选择资源。
4. 选择网格或面板对应修复，在相同窄屏重新检查，业务 SKU 和数量应一致。
5. 补查 768、1440 及键盘路径，恢复模拟设置；大视口不能单独证明窄屏通过。
6. 列出本轮未覆盖的真机检查，再选择原因、证据和验证。

## 独立挑战与答案

跨尺寸验证并列出真机检查项。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | 商品网格固定最小宽度撑出窄视口 | 390 CSS px 下网格右边界超出根视口 | 改为可收缩网格，跨尺寸保留功能 |
| 配置2 | 筛选面板仍是桌面固定宽度 | 打开筛选后面板宽度超过实际视口 | 将筛选面板限制在可用视口内 |
| 干扰项 | 提高 DPR 就能修复 CSS 网格 | 只在 1440 截一张图 | 把设备截图缩小但不改布局 |

## 三级提示

1. 准备故障，在 Device Mode 设 390 CSS px 并记录实际 innerWidth；本课检查需在 280–500 的窄视口进行。
2. 改变 DPR 与方向，读当前图片 currentSrc、pointer / hover 条件；浏览器可自行选择资源。
3. 比较两种可能原因：商品网格固定最小宽度撑出窄视口；筛选面板仍是桌面固定宽度。用本次实际证据选择最小对照。

## 边界、恢复与来源

固定版本、设备、限速、状态和类别；保留正常 SKU / 数量。真实报告、页面结果与工具操作分列，结束后恢复覆盖、视口和限速；不把课堂结论当作全面质量认证。
