# 52 · Overrides 与 Changes

由 pnpm docs:lessons 生成。内容源 src/data/quality.json；生成与合同 scripts/generate-quality.mjs。本页含教师参考答案。

## 学习目标与原理

覆盖资源、检查差异并理解作用范围。Local overrides 在浏览器本地替换匹配资源 / 响应头，不能修复服务器和代码仓库；Changes 跟踪 DevTools 编辑，Workspaces 才涉及映射源文件。

### 稳定资源地址

本会话 product.json 地址在各运行之间保持稳定，便于真实覆盖；更换 token 则匹配地址改变。缓存 / Service Worker 也可能影响判断。

### 覆盖与服务器对照

本页服务器对照会真实改变服务响应；手工覆盖入口保持故障服务响应，重新读取同一 URL。页面不声称能够读取 Overrides 开关。

### 差异与恢复

在 Sources / Elements 修改演示 CSS，用 Changes 看 diff、复制或撤销。JSON 覆盖并不等于仓库修改；用 Network 覆盖标记与原始响应 / 禁用后复现确认。

## 交互演示

切换原始与覆盖响应并恢复。切换服务器响应、本地覆盖与工作区；逐字段比较原始与覆盖数据；禁用覆盖，确认原故障是否仍可复现。模型不计完成。

## 商城实战

接口仍返回 HTTP 200，但单价类型错误导致计算失败，或 stock=null 让商品错误地显示售罄。

1. 准备故障，执行商品请求，在 Network 找 HTTP 200 的 product.json，检查 unitPrice 类型或 stock。
2. 在 Sources > Overrides 选择专用临时目录并按 Chrome 提示授权；从 Network Override content 或 Sources 保存本地覆盖。
3. 只修改当前错误字段为本课正常输入，保持 SKU、数量和其它字段；观察 Network 的覆盖标记。
4. 点“检查手工覆盖”重新读取同一 URL；它不会修正服务器数据。也可单独使用“应用所选服务器对照”作正常参考，二者不混称。
5. 在 Elements > Styles 修改本页 product.css 的价格颜色，在 Changes 看 CSS 增删 diff；恢复原值并确认 File is identical to its unmodified state。若当前版本提供 Revert，可另测该按钮；说明 Overrides、Changes、Workspaces 与仓库落盘的差别。
6. 禁用 / 删除本课覆盖并恢复故障，确认原响应仍错；恢复所有工具设置，再提交依据与最小验证。

## 独立挑战与答案

用最小修改验证新猜想并说明落盘范围。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | HTTP 200 的 unitPrice 是字符串而不是数值 | product.json 单价类型与页面计算错误对应 | 只将单价改为正常数值，保留其它字段 |
| 配置2 | stock=null 被页面当作无库存 | product.json 的 stock=null 与错误售罄对应 | 只恢复实际库存，保持 SKU 与价格 |
| 干扰项 | 有 HTTP 200 就说明业务数据一定正确 | 只凭界面变好了，没有检查实际响应 | 把计算错误的组件隐藏 |

## 三级提示

1. 准备故障，执行商品请求，在 Network 找 HTTP 200 的 product.json，检查 unitPrice 类型或 stock。
2. 只修改当前错误字段为本课正常输入，保持 SKU、数量和其它字段；观察 Network 的覆盖标记。
3. 比较两种可能原因：HTTP 200 的 unitPrice 是字符串而不是数值；stock=null 被页面当作无库存。用本次实际证据选择最小对照。

## 边界、恢复与来源

固定版本、设备、限速、状态和类别；保留正常 SKU / 数量。真实报告、页面结果与工具操作分列，结束后恢复覆盖、视口和限速；不把课堂结论当作全面质量认证。
