## 学习目标与先修

使用搜索、格式化、Source Maps 与 Ignore List。前置：已完成前 12 课或掌握等效基础。

## 原理与交互演示

Source Maps 将运行代码对应到原始源码。文件可见不代表断点映射有效，需要以实际命中验证。

页面演示：在构建代码与原始源码间映射。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 切换 generated / original。
2. 选择源文件。
3. 比较映射位置。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 运行文件和作者文件可能不同

浏览器执行 JavaScript；项目可能由 TypeScript 编译而来。Sources 中看到原始 TS 不表示浏览器直接运行 TS，而是 Source Map 把位置对应回作者文件。

### 映射依赖实际文件

编译 JS 的 sourceMappingURL 指向 .map，map 包含来源和位置。本课同时提供可获取的原始 TS 与 sourcesContent；关闭映射或丢失文件时会看到不同来源视图。

### 定位业务入口比扫文件更有效

按函数名搜索 calculateTotal，再跟进优惠字段和 applyDiscount。先找到输入到结果的短路径；pretty print 只重新排版，不能凭空恢复原始变量和类型。

## 商城实战与实验合同

症状：合计异常发生在编译后的 cart 模块。

正常结果：优惠只应用一次，合计等于单价 × 数量 − 优惠。

实现与可观察对象：真实 TS 编译 JS + .map + sourcesContent；Sources 开启 JavaScript source maps，定位 calculateTotal。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Sources 用 Ctrl/Cmd+P 找 shop-cart.ts；在 Settings → Preferences → Sources 确认 JavaScript source maps 已开启。
3. 搜索 calculateTotal，查看优惠读取和 applyDiscount 调用；对照已部署的 cart-compiled.js 与 .map 来源。
4. 在相关语句行号处设断点，点「再次触发业务」；核对 config 与调用次数，Resume 后检查合计。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 独立挑战与答案

不依赖文件名定位优惠计算入口。挑战变更输入与故障配置，不能仅凭引导案例的位置或数值选择。先复现并修复，再回教程选择原因、证据和验证。

| 配置 | 原因 | 可核对证据 | 参考修复/验证 |
| --- | --- | --- | --- |
| 配置1 | 优惠读取了错误字段 | 映射后的 calculateTotal 读取了不存在的 coupon 字段 | 读取正确的优惠字段 |
| 配置2 | 优惠被应用了两次 | 映射后的 applyDiscount 调用次数 | 只应用一次优惠 |

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Sources 搜索 calculateTotal；打开 shop-cart.ts，在 cart-compiled.js 的调用对应处设断点并触发结算。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

Source Map 提供映射，不改变正在执行的编译代码；pretty print 不等于恢复 TypeScript。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
