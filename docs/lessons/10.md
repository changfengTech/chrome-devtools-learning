## 学习目标与先修

## 原理与交互演示

堆栈能帮助回到调用者。区别异常抛出位置、错误数据来源和最终显示位置。

页面演示：沿堆栈回到调用者。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 点击堆栈帧。
2. 对比抛出点与调用入口。
3. 检查错误数据。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 错误消息说的是失败操作

toUpperCase 需要可用的字符串；对 null 或 undefined 调用会抛出 TypeError。先读错误提到的属性，再找抛出时真正的值。

### 堆栈按调用关系追上去

最上方通常是当前抛出帧，下面是调用者。readProductName 失败不一定表示错误数据在这里产生；沿 buildSummary、checkout 检查入参是谁构造的。

### 修复要符合业务语义

字段拼错应该读正确字段；确实允许缺失时，给出明确回退值或错误状态。随手加可选链可能隐藏结算失败，仍要检查最终摘要。

## 商城实战与实验合同

症状：商品字段为空，或者读取了错误字段，导致结算抛出 TypeError。

正常结果：结算生成当前商品的大写名称摘要。

实现与可观察对象：readProductName ← buildSummary ← checkout；真实 TypeError，分别为 name 为 null 与 title 为 undefined。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. 运行故障，Console 展开 TypeError，点击 readProductName 的源位置。
3. 沿 Call Stack 查看 readProductName ← buildSummary ← checkout；必要时在出错行设断点后再次触发。
4. 在抛出帧检查 product.name、product.title 及 typeof，核对调用者构造的对象，再验证正确摘要。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Console 展开 TypeError，点击 readProductName，再检查 checkout → buildSummary → readProductName 的入参。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

堆栈最上方是抛出位置，调用者负责传入数据；不要只修最后一行日志。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
