# 41 · 读懂堆快照

由 pnpm docs:lessons 生成。内容源 src/data/memory.json；生成与合同 scripts/generate-memory.mjs。本页含教师参考答案。

## 学习目标与原理

认识 Shallow/Retained Size 与 Retainers。Shallow Size 是对象自身成本，Retained Size 依赖支配关系；共享对象不能随意重复归给每个所有者。沿 Retainers 追到根，再判断该引用是否必要。

### Shallow 与 Retained

一个很小的 owner 可以经数组保留大量载荷。Retained Size 描述它消失后可随之不可达的对象，不能用字段数量推算。

### 共享与支配

两个根共享同一载荷，删除一个引用不一定释放载荷；要观察所有通往根的保留路径。

### 快照中的对象身份

Summary 按构造函数查找 CatalogCacheOwner、ProductPayload，展开实例与 Retainers。不要通过 Console 临时变量或选中 DOM 人为增加根。

## 交互演示

操作引用图观察保留关系。选中 owner、载荷并比较示意 shallow / retained；切换第二个根引用；断开一个或全部根，再解释共享对象何时不可达。模型不计完成。

## 商城实战

商品缓存管理器只含几个字段，却通过 entries 留住大量商品载荷；另一组有两个所有者共享载荷。

1. 准备空闲页，拍 Heap snapshot A，并在 Summary 认识构造函数和 Shallow / Retained Size。
2. 准备故障，重复打开商品；拍 B，筛选 CatalogCacheOwner 和 ProductPayload。
3. 展开 owner 的 entries 与 Retainers，记录 Window → memoryLab → owners 的路径。
4. 另一配置有主缓存与审计缓存共享载荷，检查两个根，不能只删一个引用就宣布释放。
5. 应用对应对照并重复相同操作，拍 C；确认根引用减少，且正常商品仍能打开。
6. 报告实际 Retainers、共享路径及快照条件；页面对象计数不冒充 Retained Size。

## 独立挑战与答案

解释大对象与保留大量对象的差异。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | 多余缓存 owner 持有重复商品载荷 | CatalogCacheOwner.entries 指向 ProductPayload | 只保留当前商品 owner，关闭后清理多余载荷 |
| 配置2 | 主缓存与审计缓存共同保留已结束的载荷 | 同一 ProductPayload 有 owners 和 audit 两条保留路径 | 同时撤销两条过期引用，保留当前业务载荷 |
| 干扰项 | Shallow Size 最大的对象必定是根因 | 只按总快照大小排序，不检查根 | 只删共享对象的一条引用 |

## 三级提示

1. 准备空闲页，拍 Heap snapshot A，并在 Summary 认识构造函数和 Shallow / Retained Size。
2. 展开 owner 的 entries 与 Retainers，记录 Window → memoryLab → owners 的路径。
3. 核对两条可能的保留或回归原因：多余缓存 owner 持有重复商品载荷；主缓存与审计缓存共同保留已结束的载荷。保持正常结果并复测。

## 边界、恢复与来源

正常结果保持 SKU、数量与业务校验值一致。相同 VM、批次和空闲条件比较；停止只清理本页资源。实际 GC、快照与 Recorder 证据须在工具核对，页面容器计数不等于堆快照。
