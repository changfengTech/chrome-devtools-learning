# 09 · 从日志中找线索

由 `pnpm docs:lessons` 生成。脚本数据：`src/data/foundations.json`；实验合同补充：`scripts/generate-foundations.mjs`。本页含教师参考答案，独立挑战前可先不阅读。

## 学习目标与先修

使用级别、过滤、分组、table 和 Preserve log。前置：已完成前 8 课或掌握等效基础。

## 原理与交互演示

日志应围绕一次用户操作组织。级别、分组与 table 帮助筛选，但最后仍需关联输入与结果。

页面演示：从混杂日志中筛选一次操作。这是可重置的教学模型，演示本身不写入实战完成记录。

1. 按级别筛选。
2. 按操作筛选。
3. 展开 group 和 table。

操作时先预测结果，再改变一个条件，比较输出；可用「重置演示」恢复初始模型。

### 先把业务信号从噪声中分离

Console 可以按文本和日志级别过滤。先搜 [checkout]，查看当前结算输入，再展开 group 和 table。过滤只影响显示，不会阻止代码执行。

### warn 与 error 不是根因标签

日志级别由编写代码的人选择。红色只提示值得检查；需要把 stock、coupon 等真实字段与最终结果对应，找出哪个输入被错误读取。

### 用值验证字段猜想

对象里 coupon 存在、couponCode 不存在时，读取后者会得到 undefined。再看计算是否回退为 0。库存同理，available 为真并不代表 stock 大于 0。

## 商城实战与实验合同

症状：结算链路混入了心跳日志，真正的优惠或库存问题被淹没。

正常结果：优惠使用正确输入；缺货订单不被接受。

实现与可观察对象：真实 group/table/warn/error；配置一读取不存在的 couponCode，配置二错误使用 available。

1. 从本课准备并打开独立商城；先打开 DevTools，再点「运行故障」。
2. Console 先清空显示，再运行故障；按 [checkout] 过滤，并依次查看 warn/error 级别。
3. 展开结算分组和 table，比较 coupon / couponCode、stock / available 与当前页面结果。
4. 用表达式检查字段存在性；应用单项修复后以相同输入复测，不能只以日志颜色消失判断成功。
5. 保持其他条件不变，手工验证或选择针对本故障的对照方案。
6. 核对正常结果与故障差异，回教程选择直接证据并记录练习。

固定数据：单价 34、数量 2、优惠 7，适用计算课的正常总额 61。第 03 课配置二故意改变数量；随机题使用本会话实际数据。

## 独立挑战与答案

区分新日志的关键线索和伴随现象。挑战变更输入与故障配置，不能仅凭引导案例的位置或数值选择。先复现并修复，再回教程选择原因、证据和验证。

| 配置 | 原因 | 可核对证据 | 参考修复/验证 |
| --- | --- | --- | --- |
| 配置1 | 优惠码字段名读取错误 | 优惠输入与 warn 记录对应 | 读取正确的 coupon 字段 |
| 配置2 | 库存字段被误读为可售 | 库存 table 与 error 记录对应 | 读取真实 stock 数值 |
| 干扰项 | 无关心跳日志太多 | 最后一条 info 日志 | 关闭所有错误日志 |

## 三级提示

1. 先稳定复现，找第一次偏离预期的结果；不要同时改变多个条件。
2. Console 过滤 [checkout]，展开分组与商品 table，找到最先出现的 warn/error，核对结算输入。
3. 比较真实值、规则或调用位置与预期。引导案例使用第一种故障，迁移案例会更换数据和故障配置。

## 误区、重置与复盘

日志级别是作者选择；一条红日志本身不证明根因，需和表格输入及结果对应。

点商城「恢复故障」可重新渲染初始案例；重新准备会话会清空当前观察与选择，不删除已保存学习记录。会话 30 分钟失效，服务重启后重新准备。修复完成后清除本课断点、恢复 caught 异常开关及网络条件；刷新清除临时 DOM/CSS 修改。

复盘记录：症状、实际证据、首次偏离位置、最小改动、复测结果，以及尚不能确定的范围。
