# 42 · 比较与追踪分配

由 pnpm docs:lessons 生成。内容源 src/data/memory.json；生成与合同 scripts/generate-memory.mjs。本页含教师参考答案。

## 学习目标与原理

比较快照并用分配分析缩小来源。Comparison 缩小存活增量，Allocation instrumentation on timeline 关联分配区间，Allocation sampling 用统计方式定位分配栈。分配多不等于保留多。

### 比较同一 VM

A：预热且空闲；B：相同操作；C：修复后重做。比较同一文档的快照身份，关注 # Delta / Size Delta，再看 Retainers。

### 分配区间

开始 Allocation instrumentation on timeline，重复开关，停止并选操作区间，区分仍存活与已回收对象。录制本身有开销。

### 抽样与精确计数

Allocation sampling 是统计估计。用 createPreviewAllocation / retainPreviewSnapshot 的分配栈找线索，再用快照和业务生命周期确认。

## 交互演示

比较重复操作后的增量和位置。增加相同操作批次；切换正常缓存与泄漏保留；比较分配总量和回收后存活增量。模型不计完成。

## 商城实战

每次关闭商品预览都会留下新会话，或保存一次新的预览快照；现象只有重复后才明显。

1. 预热页面并记录 A，在相同 VM 进行 5 次预览开关，再拍 B。
2. 在 Comparison 选择 A，筛选 PreviewAllocation，记录 # Delta 和 Retainers。
3. 开启 Allocation instrumentation on timeline 后重复一组，停止并选择操作区间检查存活条目。
4. 另用 Allocation sampling 找 createPreviewAllocation / retainPreviewSnapshot；抽样次数不等于精确对象数。
5. 应用当前配置对应对照，保持同样工作量做 C；正常 latestPreview 可以保留一个。
6. 至少比较两批趋势，记录增量、分配来源、引用根和修复后正常功能。

## 独立挑战与答案

区分正常存活和可疑增量。输入与故障随机变化，可能再次抽到同类。

| 配置 | 根因 | 证据 | 针对性验证 |
| --- | --- | --- | --- |
| 配置1 | previewHistory 每次追加关闭后的预览对象 | Comparison 中 PreviewAllocation 随批次净增，根为 previewHistory | 移除关闭预览历史，保留至多一个当前预览 |
| 配置2 | snapshotCache 按每次访问 ID 保存快照 | 分配栈 retainPreviewSnapshot，根为 snapshotCache 的不同键 | 按商品复用快照并限制缓存 |
| 干扰项 | 分配量大就一定泄漏 | 只有抽样热点，没有存活与引用证据 | 仅强制 GC，不断开引用 |

## 三级提示

1. 预热页面并记录 A，在相同 VM 进行 5 次预览开关，再拍 B。
2. 开启 Allocation instrumentation on timeline 后重复一组，停止并选择操作区间检查存活条目。
3. 核对两条可能的保留或回归原因：previewHistory 每次追加关闭后的预览对象；snapshotCache 按每次访问 ID 保存快照。保持正常结果并复测。

## 边界、恢复与来源

正常结果保持 SKU、数量与业务校验值一致。相同 VM、批次和空闲条件比较；停止只清理本页资源。实际 GC、快照与 Recorder 证据须在工具核对，页面容器计数不等于堆快照。
