## 在线迁移中修复的问题

- Node 处理器内存会话改为可注入状态；线上用 D1 保存并保留原会话有效期。
- Map、Set、Buffer、公钥显式序列化；并发写用 revision 条件更新和变更合并，八个并行请求的资源观察均保留。
- 保留真实响应头前等待、流式主体、SSE 与 WebSocket，不将整段响应提前缓冲成模拟耗时。
- 网站 HTTPS / RP、审计 URL 归属、CORS 同伴、wss、手机入口与来源检查分别适配；没有放开任意来源。
- 同伴只转发课程需要的头部，不传递 Cookie、Authorization 或平台内部路由头。
- 网络不可达时提示在线连接重试，不让在线用户误以为必须启动本地服务；依赖本地磁盘、真机或账户的步骤单独说明。

## 在可达网络完成退出验收

1. 课程与商城健康连接成功；第 05、21、24 各完成一轮实际故障 / 修复 / 教程回传，至少完成一个独立挑战并确认错误证据被拒绝。
2. Network / Application 检查真实跨域、Cookie、304、worker、离线缓存和连接消息；不同来源与会话的存储互不混用。
3. Performance / Memory / Lighthouse 使用独立商城页采集实际原生证据；报告导入来源和运行编号仍受约束。
4. 章末生成、保留报告、学习记录导入导出与重载均完成后，才将线上完整流程改记为通过。
5. Android、定位权限、AI 可用账户和目录授权按 [额外条件](DEPLOYMENT.md#原生工具与额外条件) 补验；不具备条件时保留待验。

CORS 同伴首页从 404 改为服务说明页，独立网络已验证三站首页返回 200。当前本机的 Sites 访问走 en0 直连并在 TLS 握手时被重置；可工作的文档域名走 utun0。用户也报告手机访问失败，不能将故障唯一归因于公司 VPN；网络链路与平台公网入口的可达性仍需继续定位，不能将未完成的浏览器验收记为通过。没有绕过证书检查、改写 DNS、建立代理或用另一网址冒充这三个已授权的 Site。
